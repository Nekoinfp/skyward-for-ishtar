## 刷入

先备份能回滚的原厂 recovery：

```bash
fastboot fetch recovery_a stock-recovery_a.img
fastboot fetch recovery_b stock-recovery_b.img
```

两个槽都刷，避免某次重启回落到旧的那一份：

```bash
fastboot flash recovery_a skyward-v0.3.1-beta1-xuanyuan-OS4.0.4.0.XOACNXM.img
fastboot flash recovery_b skyward-v0.3.1-beta1-xuanyuan-OS4.0.4.0.XOACNXM.img
fastboot reboot recovery
```

进 recovery 后，到「解密」页输入你平时的**锁屏 PIN/密码**，`/data` 与内部存储就都能读。

> 连续输错会被手机的 secure world 计数（和锁屏上一样），别乱试。

## 这一版做了什么

这是把上游 0.3.1 适配到这台手机的第一个真机可用版本。

### /data 完整解密（本适配的核心）

手机用 metadata 加密 + `wrappedkey_v0`，密钥要靠 keymint、gatekeeper、weaver、eSE
一整条链路才能解开。这一版把整条链路接通：

- 六个密钥服务全部注册（keymint / gatekeeper / secure_element / eSE omapi / weaver / boot）
- **设备加密（DE）与用户加密（CE）都能打开**：`/data`、`/data/data`、`/sdcard` 均可读
- 修掉了两个真实故障：
  1. **keymint 缺库**：`libvndksupport.so` 只在 system 里，而 keymint 是 vendor 程序。
     现在按机型配置把这些库放到它找得到的地方。
  2. **`-62 KEY_REQUIRES_UPGRADE`**：用户的 synthetic password 密钥是旧系统版本下生成的，
     KeyMint 要求先续期。以前只重启 keymint 再试同一个密钥（无效，永远第二次同样报错）；
     现在**真正调用 `upgradeKey`** 用续期后的 blob 去开，续期结果只留内存、不写回手机。

### 压缩快照（VABC）可读

系统更新后产生的快照是 lz4 压缩的、由手机自己的 `snapuserd` 在用户态服务的。
这一版把 `snapuserd` 一起打进 ramdisk，并在 `init` → 建设备 → `start` 之后挂载：

- 实测系统更新产生的 **9 个 lz4 快照分区全部挂载成功**，六个密钥服务从快照里的分区正常注册
- 三条协议细节是从手机自己的报错里学到的：内核 target 名是 `user`（不是 `dm-user`）、
  表参数必须是 3 段 `0 0 <名字>`、`init` 要 5 段

### 屏幕与触摸

1440×3200@120 正常点亮、触摸可用、双击唤醒、recovery 服务重启时重新唤醒触摸控制器。

### 界面与操作

- **多选刷入**：文件页点文件打勾，底部条「安装选中的 N 个」依次装完，不用反复翻文件夹
- **单独分区刷入**：刷 `.img` 时可选择只刷 boot / init_boot / vendor_boot / recovery /
  dtbo / vbmeta 中的某个，并选槽位
- **红字警告**：安装页与系统更新页都标明「在 recovery 中安装官方完整包大概率导致系统卡米，
  请在系统内完成更新」
- **大字号字形修复**：About 页 wordmark 的 y 曾因 ab_glyph 对可变字体在大字号 + 分数位置
  的光栅化缺陷而显示成灰方块。现在大字号按整像素定位，字形完整
- 版本号改为 `0.3.1-beta1`（此前叫 1.1.0，对上游 0.3 的适配而言夸大了），
  About 页在版本下增加一行 `Skyward by xuanyuan`

## 已知限制

- **不要在 recovery 里装官方完整包**：装完大概率卡米（安装本身成功，但更新包把 boot/vbmeta
  刷成原厂，这一代小米 bootloader 的签名校验绕不过 `disable-verification`）。请在系统内更新。
  真卡米了也别慌：把备份的 boot 刷回两个槽、`fastboot set_active` 重置计数即可，实测
  15 秒起机、数据完好。
- **压缩快照的合并**没开启。`skyward merge --compressed` 实测 9 个分区只有 1 个能完成，
  其余停在 `snapshot-merge`。退路可靠：重启进系统，系统一分钟内自己合并完。
- **逻辑分区就地扩容做不到**：super 里没有对齐的空闲区（唯一空洞 1 MB）。
- 增量更新包与非 A/B 更新包未实现。

## 从旧版升级

如果你刷过更早的 1.1.0，直接按上面的 `fastboot flash` 覆盖两个槽即可，配置与数据不受影响。

## 校验构建

镜像结构审计 32 项全过（boot 头、ramdisk 解包为 newc、`system/bin/recovery` 为 AArch64 ELF、
`system/bin/skyward` 指向它、AVB footer 指向的 vbmeta 中哈希描述符的摘要确实等于
`sha256(salt + 镜像)`、属性描述符携带底包 fingerprint）。同一份镜像重建两次哈希相同。

详细验证记录见仓库的 `docs/xuanyuan-verification.md`。
